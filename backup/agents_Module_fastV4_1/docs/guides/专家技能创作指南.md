# 专家技能创作指南

本指南介绍如何使用 SkillsManager Agent 的专家技能创作功能，让专业摄影师通过自然语言输入分享经验，并将其转化为结构化的拍摄技能。

---

## 功能概述

### 核心流程

```
专家自然语言输入
    ↓
SkillsManager 提取结构化技能
    ↓
保存到 pending_review/ 待审核
    ↓
用户交互式审核
    ↓
保存到 personal/ 或 builtin/ 或取消
```

### 目录结构

```
skills/repository/
├── builtin/               # 内置技能库
│   ├── common/           # 通用技能（适用于所有阶段）
│   ├── director/
│   │   ├── portrait/     # 人像
│   │   ├── landscape/    # 风景
│   │   ├── product/      # 产品
│   │   └── sports/       # 运动
│   ├── cinematographer/
│   │   ├── portrait/
│   │   ├── landscape/
│   │   ├── product/
│   │   └── sports/
│   └── editor/
│       ├── portrait/
│       ├── landscape/
│       ├── product/
│       └── sports/
├── personal/             # 个性化技能库（用户自定义）
│   ├── common/
│   ├── director/
│   ├── cinematographer/
│   └── editor/
├── pending_review/       # 待审核技能
└── skill_index.json      # 技能索引表
```

## 技能分类说明

### stage（阶段）

| 值 | 说明 | 适用场景 |
|---|---|---|
| `director` | 拍摄前规划 | 构图规划、镜头设计、拍摄方案 |
| `cinematographer` | 实时拍摄 | 画面跟踪、实时调整、捕获时机 |
| `editor` | 后期剪辑 | 时间线规划、节奏控制、素材选择 |
| `common` | 通用技能 | 适用于所有阶段的基础原则 |

### category（类型）

| 值 | 说明 | 示例 |
|---|---|---|
| `portrait` | 人像 | 人物特写、人物故事、情绪捕捉 |
| `landscape` | 风景 | 自然风光、城市景观、天空地貌 |
| `product` | 产品 | 商业产品、静物摄影、电商图片 |
| `sports` | 运动 | 体育赛事、动作捕捉、快速跟踪 |
| `common` | 通用 | 不限于特定类型的技能 |

## 智能合并功能

当保存新技能时，系统会自动检测相似的现有技能：

### 检测逻辑

1. **相同 stage 和 category**
2. **相似的名称**（包含关系检测）

### 合并策略

- **规则合并**：避免重复，只添加新的独特规则
- **标签合并**：合并所有唯一标签
- **时间戳更新**：记录最后修改时间

### 示例

**现有技能**：`clean_product_director.yaml`
- 规则数量: 5 条

**新输入**：专家分享了 2 条新规则

**合并结果**：
- 保持原有 5 条规则
- 添加 2 条新规则（如果不重复）
- 总规则数: 7 条

## 高级用法

### 1. 创建通用技能

适用于所有阶段的基础原则：

```bash
python test_agents.py skills-author --mode bailian --expert-input "构图时始终遵循三分法则，将主体放在画面的交叉点上。这样可以创造平衡且有视觉吸引力的画面。"
```

系统会自动识别为 `stage: common`。

### 2. 创建跨类型技能

适用于多种拍摄类型的技能：

```bash
python test_agents.py skills-author --mode bailian --expert-input "无论拍摄什么题材，我都会注意前景、主体和背景的层次关系。前景增加深度，背景避免干扰。"
```

系统会自动识别为 `category: common`。

### 3. 批量创建技能

创建脚本批量处理多个专家输入：

```python
expert_inputs = [
    "拍摄风景时，黄金时刻的光线最柔和...",
    "运动摄影需要快速连拍和跟踪对焦...",
    "产品摄影要注意避免反光..."
]

for text in expert_inputs:
    result = app.manager.author_from_expert(text)
    # 自动保存到 personal
    app.manager.review_and_save(result['skill_id'], 'personal')
```

## 最佳实践

### 1. 输入专家经验时

✅ **好的输入**：
```
"拍摄人像时，我会让模特面向主光源，确保眼睛有眼神光。
逆光时，我会使用反光板补光，避免脸部太暗。
构图上，我喜欢留出视线方向的空间，让画面更有呼吸感。"
```

❌ **不好的输入**：
```
"人像很重要"
```

**原因**：详细的输入能提取更丰富的规则。

### 2. 选择保存位置

- **personal**：个人风格、实验性技能、特定项目需求
- **builtin**：经过验证的通用技能、团队共享的标准
- **cancel**：提取错误或不需要的技能

### 3. 合并 vs 新建

**选择合并**：
- 新规则是对现有技能的补充
- 同一主题的不同细节

**选择新建**：
- 完全不同的拍摄思路
- 不同风格的处理方式

## 常见问题

### Q1: 为什么提取的技能不准确？

**A**: 确保使用 `--mode bailian` 调用真实的 LLM API。Mock 模式只返回基础结构。

### Q2: 如何查看所有待审核的技能？

**A**: 查看 `skills/repository/pending_review/` 目录：

```bash
ls skills/repository/pending_review/
```

### Q3: 如何删除错误的技能？

**A**: 
1. 如果在 pending_review，选择 "3. cancel"
2. 如果已保存，直接删除对应的 YAML 文件，并重建索引：

```python
from fast import ScenePilotFast
app = ScenePilotFast(mode="bailian")
app.skills._rebuild_index()
```

### Q4: 技能索引表损坏怎么办？

**A**: 重建索引：

```python
from fast import ScenePilotFast
app = ScenePilotFast(mode="bailian")
app.skills._rebuild_index()
print("索引已重建")
```

### LLM 提取的字段

```json
{
  "name": "英文名称",
  "name_zh": "中文名称",
  "description": "英文描述",
  "description_zh": "中文详细描述",
  "stage": "director/cinematographer/editor/common",

  "tags": ["标签1", "标签2"],
  "rules": [
    {
      "condition": "触发条件（英文）",
      "condition_zh": "触发条件（中文）",
      "action": "建议操作（英文）",
      "action_zh": "建议操作（中文）",
      "reason": "原因说明（中文）"
    }
  ],
  "confidence": 0.85
}
```

### YAML 文件格式

```yaml

description: Portrait shooting during golden hour
language: en
author: expert
status: active
stage: director
category: portrait

  - portrait
  - golden_hour
  - natural_light

agent_bindings:
  director: true

rules:
  - condition: golden_hour_time
    action: face_towards_light
    priority: high
    reason: Soft golden hour light creates flattering portrait lighting

metadata:
  created_at: "2024-01-15T14:30:00Z"
  updated_at: "2024-01-15T14:30:00Z"
  version: "1.0"
```
