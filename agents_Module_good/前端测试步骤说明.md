## 第八步：测试 Editor 工作区双视频过渡

这是独立的 Editor Demo，不是普通 `Editor Agent` 的单视频粗剪接口。

### 8.1 前端输入

点击：

### 8.2 工作流程

```text
v1 最后一帧
v2 第一帧
    -> DashScope 首尾帧视频任务
    -> 轮询任务
    -> 下载 transition.mp4
    -> FFmpeg 统一规格
    -> 拼接 v1 + transition + v2
```

统一规格：

```text
1280x720
30fps
无音频
```

### 8.3 输出位置

```text
outputs/editor_workspace/
  frames/<workspace_id>_v1_last.jpg
  frames/<workspace_id>_v2_first.jpg
  normalized/<workspace_id>_v1.mp4
  normalized/<workspace_id>_v2.mp4
  transitions/<workspace_id>_transition.mp4
  renders/<workspace_id>_output.mp4
  <workspace_id>.json
```

前端响应中的 `data.output_video` 是最终视频路径。

### 8.4 如果生成失败

先查看响应中的：

```json
{
  "transition": {
    "used": false,
    "fallback": "具体错误"
  }
}
```

常见原因：

1. `.env` 只有文本/视觉模型配置，没有视频模型配置。
2. `DASHSCOPE_VIDEO_MODEL` 不是账号实际可用的首尾帧视频模型。
3. `DASHSCOPE_VIDEO_API_URL` 使用了错误的 API 类型。
4. 视频模型请求字段和官方文档不一致。
5. 首尾帧使用 data URL，但当前视频模型只接受公网 URL 或 OSS URL。
6. 视频生成任务需要专用地域、权限或额度。
7. 任务创建成功，但状态查询 endpoint 不正确。
8. 任务成功，但响应字段不是当前代码读取的 `output.video_url`。

### 8.5 纯 FFmpeg 降级测试

## 第九步：测试 Cinematographer 摄像头多轮会话

当前实现的是本地会话记忆，不依赖模型服务端自动记忆。首次启动时发送：

```text
用户目标 + Cinematographer Skills
```

之后每次只发送当前摄像头图片，同时服务端保存最近几次分析摘要作为短记忆。浏览器每 0.5 秒提交一帧，直到用户手动点击停止。

### 9.1 启动条件

浏览器摄像头权限要求：

- 直接打开 `file://` 页面时，部分浏览器会拒绝摄像头权限。
- 推荐使用 `localhost` 静态服务器。
- API 服务仍运行在 `http://127.0.0.1:8765`。

启动前端静态服务器：

```powershell
cd F:\BoldMaker\project00\agents_Module_fast\frontend
python -m http.server 5500
```

打开：

```text
http://127.0.0.1:5500
```

### 9.2 前端操作

1. 启动 FastAPI：

```powershell
cd F:\BoldMaker\project00\agents_Module_fast
python fast.py serve --mode bailian
```

2. 打开前端页面。
3. 在“用户需求”中输入：

```text
请实时指导我拍摄自然的人像，让人物脸部清晰，人物看向哪边就在那边留空间。
```

4. 点击“启动摄像头会话”。
5. 在浏览器弹窗中允许摄像头权限。
6. 系统每 0.5 秒发送一帧给：

```text
POST /api/v1/agents/cinematographer/session/{session_id}/frame
```

7. 根据模型输出调整位置：

```text
move_forward
move_backward
move_left
move_right
adjust_angle
capture_frame
wait_and_recheck
```

8. 用户手动点击“手动停止”。

### 9.3 会话接口

启动：

```http

```

```json
{
  "user_text": "自然人像实时拍摄指导",
  "skills_filter": {
    "stage": "cinematographer",
    "limit": 3
  }
}
```

逐帧分析：

```http
POST /api/v1/agents/cinematographer/session/{session_id}/frame
```

```json
{
  "frame_data": "data:image/jpeg;base64,..."
}
```

停止：

```http
POST /api/v1/agents/cinematographer/session/{session_id}/stop
```

### 9.4 输出结果

每一帧响应包含：

- 当前帧路径。
- 当前画面分析。
- 当前动作建议。
- 当前构图建议。
- 是否抓拍。
- 抓拍文件路径。
- 当前会话 ID。

抓拍结果保存到：

```text
outputs/cinematographer_sessions/<session_id>/captures/
```

停止后会保存：

```text
outputs/cinematographer_sessions/<session_id>/session.json
```

### 9.5 关于“模型是否记得之前的要求”

不要依赖 API 服务端自动记忆。当前实现由本地服务维护会话：

```text
首次请求：用户目标 + Skills + 当前帧
后续请求：当前帧 + 最近几次分析摘要
```

这样可以控制上下文长度和成本，也能在服务重启后明确判断会话是否仍然有效。

### 9.6 注意事项

- 每 0.5 秒调用一次百炼会产生较高 API 消耗和延迟。
- 如果单次请求超过 0.5 秒，浏览器请求可能重叠；正式版本应增加前端发送锁或服务端队列。
- 当前版本不自动停止，必须手动点击停止。
- `capture_frame` 只保存浏览器发送到服务端的当前帧，不会触发真实相机拍照。
- 真实相机拍摄需要后续 DeviceExecutor/相机 SDK 接入。

### 9.7 关于 X4 Air/Link2 和多路视频流

当前浏览器摄像头只是测试适配器。最终设备数据流应通过本地设备适配器转换为统一帧：

```json
{
  "stream_id": "x4air_main",
  "device_id": "x4air_serial_001",
  "timestamp_ms": 12400,
  "sequence": 248,
  "frame_data": "data:image/jpeg;base64,..."
}
```

Link2 可以通过 UVC/Link SDK 输出帧，X4 Air 可以通过官方预览或 Camera/Media SDK 输出帧，最终都接入同一个 Cinematographer Session。

架构上支持：

```text
BrowserCameraAdapter
Link2Adapter
X4AirAdapter
        |
        v
Cinematographer Session
```

但当前项目还没有实现：

- X4 Air 适配器。
- Link2 适配器。
- 多路流 `stream_id` 调度。
- 多流同步/融合。
- 真实相机抓拍。

因此本页的浏览器会话测试只能证明“会话记忆、逐帧分析、建议和抓帧保存”有效。拿到真实设备后，应先实现 `VideoFrame` 适配器，再复用现有会话接口，不要重写 Cinematographer Agent。

### 9.8 最终设备接入预期

电脑摄像头只是测试输入，最终接入应为：

```text
X4 Air / Link2
    -> 本地设备适配器
    -> VideoFrame
    -> Cinematographer Session
    -> Qwen-VL 分析
    -> 构图/移动/抓拍建议
```

多路设备示例：

```text
link2_main
x4air_environment
link2_closeup
```

每一路必须有独立 `stream_id`，不能混用同一个会话记忆。当前前端只采集单路浏览器流，但 API 已支持同一会话注册多个流并按 `stream_id` 隔离状态；真实 X4 Air/Link2 设备适配器和持续多流调度尚未实现。

### 9.9 同一会话注册多条输入流

新增设备流：

```http
POST /api/v1/agents/cinematographer/session/{session_id}/streams
```

```json
{
  "user_text": "沿用启动会话时的目标",
  "stream_id": "x4air_wide",
  "source_type": "x4air_preview",
  "device_id": "x4air_serial_001"
}
```

向指定流发送帧：

```http
POST /api/v1/agents/cinematographer/session/{session_id}/frame
```

```json
{
  "stream_id": "x4air_wide",
  "timestamp_ms": 12400,
  "sequence": 248,
  "frame_data": "data:image/jpeg;base64,..."
}
```

推荐流 ID 示例：

```text
link2_main
link2_closeup
x4air_wide
```

当前 `CinematographerSessionStore` 对每条流隔离帧序号、短记忆和抓拍目录。接入 X4 Air/Link2 时，需要本地设备适配器持续读取预览流，再按上面的格式提交帧；设备读取、帧调度和 SDK 抓拍仍需单独实现。

## 8. 常见错误

### API Key 没有加载

错误通常类似：

```text
Bailian mode requires API key
```

检查：

```powershell
python -c "from dotenv import load_dotenv; import os; load_dotenv('.env'); print(bool(os.getenv('DASHSCOPE_API_KEY')))"
```

### 模型不存在

检查：

```env
DASHSCOPE_MODEL=qwen-vl-plus
```

如果账号不支持该模型，替换为百炼控制台中实际可用的视觉模型。

### 401 错误

通常是：

- API Key 错误
- API Key 和 Base URL 地域不一致
- Key 已失效

### 400 错误

可能是：

- 模型不支持当前多模态请求格式
- 图片路径不存在
- 图片格式不支持
- 请求内容过大
- API 输入 JSON 不符合模型要求

### 前端跨域错误

当前服务已经配置 CORS。如果仍然出现跨域错误，可以不要直接双击 HTML，而是启动一个静态文件服务器：


然后打开：

```text

```

API 服务仍然运行在：

