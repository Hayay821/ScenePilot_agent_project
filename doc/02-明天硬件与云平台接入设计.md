# 明天硬件与云平台接入设计

目标：领取 X4 Air、Link 2 和官方云资源后，把今晚的 `VideoSource`、`DeviceAdapter`、`SemanticProvider` 替换为真实实现，不重写上层算法。

## 1. 明天第一小时：只做能力探测

### X4 Air

1. 激活相机、检查固件、电量、存储卡和 USB 数据线。
2. 运行官方 Desktop Camera SDK 示例，确认发现、连接、预览、开始/停止录像、文件列表和下载。
3. 运行 Desktop Media SDK 示例，确认 `.insv -> .mp4` 拼接导出。
4. 若 USB SDK 不稳定，连接相机 Wi-Fi，测试 `/osc/info`、`/osc/state` 和 `camera.getOptions`。
5. 保存相机能力表和一段 10 秒样片，不要直接假设所有文档字段均受 X4 Air 固件支持。

### Link 2

1. 连接 USB，确认系统能作为 UVC 设备读取视频。
2. 编译运行 Link-SDK 对应平台示例。
3. 枚举设备并读取序列号、机型、PID、固件和 MediaFormat。
4. 测试绝对 Pan/Tilt、跟踪模式、构图、追踪速度、手势开关、曝光和音频模式。
5. 测试程序退出和异常时发送 PTZ Stop，并释放控制器。

每项结果写为 `supported/unsupported/error`，不能只记“应该支持”。

## 2. 硬件架构

官方 X 系列桌面 SDK 和 Link UVC SDK 均以 C++ 为主。建议各自运行独立设备桥进程：

```text
Python AI Service
  | HTTP/WebSocket localhost
  +--> x4air-bridge (C++)
  |      Camera SDK: USB 发现、预览、拍摄、文件
  |      Media SDK: 拼接、实时拼接、导出
  |      OSC fallback: Wi-Fi HTTP 控制
  |
  +--> link2-bridge (C++)
         UVC capture: 视频流
         UVCCameraController: PTZ/曝光/对焦/画质
         UVCCameraExtendController: 模式/追踪/构图/手势/音频
```

不建议直接用 Python `ctypes` 包装全部 C++ SDK。独立进程更容易隔离 ABI、驱动、USB 重连和崩溃问题，也方便 Claude Coding 分模块开发。

## 3. 设备桥统一协议

### 3.1 能力查询

`GET /v1/capabilities`

```json
{
  "device_id": "link2-serial",
  "device_type": "link2",
  "capabilities": {
    "video_stream": true,
    "pan_tilt_absolute": true,
    "tracking": true,
    "composition": ["head", "half_body", "full_body"],
    "gesture": true,
    "audio": true
  }
}
```

所有控制前必须查询能力；不支持的 UI 和动作应隐藏或拒绝。

### 3.2 命令提交

`POST /v1/commands`

```json
{
  "command_id": "cmd-001",
  "action": "set_pan_tilt_absolute",
  "args": {"pan_deg": 20.0, "tilt_deg": 5.0},
  "deadline_ms": 1000
}
```

响应必须包含实际执行结果，不得只返回“已接收”。

### 3.3 状态与事件

WebSocket `/v1/events` 输出：连接、断开、录制状态、温度/错误、文件生成、命令结果。上层根据设备断开切换到 Mock 或全景兜底模式。

## 4. X4 Air 接入

### 4.1 首选：桌面 Camera SDK + Media SDK

Camera SDK 用于：

- USB 设备发现、连接和断开。
- 查询能力表、状态和拍摄参数。
- 开始/停止拍照或录像。
- 预览流。
- 文件信息、录制中列表和文件下载。官方文档注明文件下载适用于 X4 及后续机型，X4 Air 应现场验证。

Media SDK 用于：

- 导入 `.insv`，导出 MP4。
- 离线全景拼接。
- 实时预览流拼接。
- 后续全景重构的标准 equirectangular 输入。

注意：Media SDK 3.x 官方文档要求独立 GPU；Windows 文件路径需 UTF-8；不能在 WSL Ubuntu 下测试。设备桥优先原生 Windows 或原生 Ubuntu 22.04。

### 4.2 备选：OSC

OSC 适合跨语言、通过 Wi-Fi HTTP 直接控制。相机默认地址通常为 `192.168.42.1`，但应现场确认。

流程：

1. `GET /osc/info`。
2. `POST /osc/state`。
3. `camera.getOptions` 查询实际支持项。
4. `camera.setOptions` 切换拍摄模式。
5. `camera.startCapture` / `camera.stopCapture`。
6. 使用返回 URL 下载文件。

官方建议 `/osc/info` 不超过每秒一次，且下一条 `/osc/commands` 应等待上一条回复。OSC 控制器必须串行化命令。

### 4.3 全景最佳视角

分成三步：

1. 官方 Media SDK 将双鱼眼素材拼接为 equirectangular 视频。
2. 在球面图像的多个候选方向做人物/主体检测，转成 `yaw/pitch`。
3. 使用平滑轨迹生成普通视角视频。

轨迹优化约束：

```text
objective = subject_center_error
          + lambda_1 * angular_velocity
          + lambda_2 * angular_acceleration
          + lambda_3 * unnecessary_cut
```

即使检测框跳动，虚拟相机也不能快速左右摇摆。对角度跨越 `-180/180` 必须做 unwrap。

## 5. Link 2 接入

### 5.1 视频流

Link 2 通过 USB UVC 输出视频，先使用 OpenCV/Media Foundation/GStreamer 读取；分辨率和帧率从官方 `GetMediaFormatList` 获取，不硬编码。

建议分两路：

- 录制路：保留高分辨率画面。
- AI 路：缩放至 640 或更低分辨率，供检测、跟踪和 STC。

同一设备可能被其他程序占用。启动时检测 OBS、Link Controller、会议软件是否正在使用视频流。

### 5.2 云台和追踪

优先利用 Link 2 官方能力：

- `SetVideoMode`：普通、自动构图、多人构图、桌面俯拍等。
- `SetCompositionStyle`：头部、半身、全身。
- `SetTrackSpeed`：快、普通、慢。
- `GetTrackObjLists` + `SetTrackObj`：选择追踪目标。
- `SetPanTiltAbsolute`：固定预设位或恢复。

官方文档中绝对位置单位为角秒，`1 度 = 3600`，Pan 大致 `[-145, 145]` 度、Tilt `[-45, 90]` 度；仍需以设备查询范围为准。

AI 导演的优先策略：

1. 能用设备内置 Track 时，优先选择目标框并让设备执行稳定跟踪。
2. 本地 tracker 监测是否丢失和构图是否满足用户目标。
3. 只有设备追踪不满足时，才由本地控制环发送 PTZ 调整。
4. 高频 PTZ 命令合并、限速，并设置停止与超时保护。

### 5.3 无接触控制

Link 2 官方 SDK支持手势总开关和 Palm/L/V 等手势能力。产品层应将手势映射到安全动作：

| 输入 | 建议动作 |
|---|---|
| Palm | 暂停/恢复跟拍，避免直接删除或格式化 |
| L | 切换构图或变焦 |
| V | 标记高光 |
| 语音“开始记录” | 同时启动 X4 Air 录制并建立 Link 2 本地录制会话 |
| 语音“跟拍红衣服的人” | 本地检测目标，模型确认目标描述，Link 2 选择目标框 |

Link SDK 中已废弃的 `Gesture_Ok` 和 `Gesture_Rock` 不应使用。

## 6. 多设备协调

### 6.1 时间同步

- 主机使用单调时钟作为统一事件时间。
- 启动录制前记录设备时间、主机时间和命令往返延迟。
- Link 2 本地录制帧直接使用主机时间戳。
- X4 Air 文件通过拍摄开始/停止回执和音频峰值二次对齐。
- 最稳妥的现场方式：开拍后在两台设备可见/可闻范围内击掌一次，使用音视频峰值对齐。

### 6.2 设备选择策略

```text
Link 2 可见主体且跟踪稳定：优先 Link 2 主镜头
主体离开 Link 2 视野：切 X4 Air 虚拟镜头
多人或方向不可预测：X4 Air 保持全景主记录
需要正面近景/语言交互：Link 2
需要空间环境、回看其他方向：X4 Air
```

切镜只生成建议和时间线；最终剪辑阶段用质量、事件和叙事规则确认。

## 7. 阿里云部署

### 7.1 GPU 云服务器

部署：

- YOLO/ByteTrack/姿态模型。
- 可选 VideoLLM-online 基线。
- 代理视频批量分析。
- FFmpeg GPU 编解码，前提是驱动与编码器可用。

设备在现场电脑上，云 GPU 无法直接访问 USB。现场电脑运行 Edge Agent，通过 WebSocket/HTTPS 发送低分辨率关键帧、事件和控制状态。高频 PTZ 闭环必须留在现场电脑，不能依赖公网往返。

### 7.2 CPU 云服务器

部署 FastAPI 控制面、用户会话、任务状态、Web UI 和日志。Redis 只在确实需要跨进程队列时加入。

### 7.3 OSS

建议路径：

```text
oss://<bucket>/<team>/<session>/raw/
oss://<bucket>/<team>/<session>/proxy/
oss://<bucket>/<team>/<session>/keyframes/
oss://<bucket>/<team>/<session>/analysis/
oss://<bucket>/<team>/<session>/renders/
```

使用服务端签名或短期 STS 权限，不把 AccessKey 放到前端。原始素材设置生命周期；上传前取得参赛者授权。

### 7.4 PAI

只有满足以下条件才使用：

- 已形成至少数百个事件窗口和人工标签。
- 基线错误有明确模式，提示词和规则无法解决。
- 有时间完成训练、验证和回滚。

优先训练小型事件分类器或 Qwen-VL LoRA，不训练全新视频大模型。比赛前两天没有可靠数据时，PAI 应用于批量评估而非盲目训练。

## 8. VideoLLM-online GPU 验证

在 GPU 服务器上作为独立实验，不阻塞主线：

1. 检查 NVIDIA 驱动、CUDA、显存和磁盘。
2. 按官方仓库固定兼容的 PyTorch/Transformers 版本，使用独立环境。
3. 先运行 30 秒视频 CLI，不直接接摄像头。
4. 测试 2 FPS、384 分辨率下的显存、吞吐和首响应延迟。
5. 再将 `Link2VideoSource` 接入流式输入。
6. 输出转换为统一 `VideoEvent` Schema。
7. 与“STC + Qwen-VL API”比较事件召回、延迟和工程稳定性。

如果显存或依赖不满足，保留百炼 API 主线，不继续消耗现场时间。

## 9. Claude Coding 硬件任务单

### Task A：Link 2 C++ Bridge

```text
基于官方 Link-SDK 示例创建最小 C++ 服务。实现设备枚举、能力查询、媒体格式查询、Pan/Tilt 绝对位置、视频模式、构图、追踪速度、追踪目标和 Stop。所有设置先读取范围/能力。提供 localhost HTTP API，并在退出、超时和异常时停止 PTZ。
```

验收：能枚举正确序列号；同一命令重复调用幂等；越界参数返回 4xx；拔线不崩溃。

### Task B：X4 Air Camera Bridge

```text
基于 Desktop Camera SDK 官方示例创建 C++ 服务。实现发现、连接、能力表、状态、开始/停止录像、预览状态、文件列表和下载。若 SDK 不可用，实现独立 OSC adapter，不混在业务层。
```

验收：10 次开始/停止录制无死锁；断连后可重新发现；命令串行执行。

### Task C：X4 Air Media Worker

```text
基于 Desktop Media SDK 示例实现离线拼接任务，将 insv 导出为 equirectangular mp4，提供任务状态、进度、日志和取消。所有路径使用 UTF-8。启动时检查独立 GPU 和模型文件。
```

验收：真实 10 秒样片可导出；失败时保留日志；不在 WSL 内运行。

### Task D：Python Adapter

```text
实现 Link2DeviceAdapter 和 X4AirDeviceAdapter，调用本地桥服务并转换成统一 CameraAction/DeviceStatus。加入能力缓存、超时、重试、熔断和 Mock fallback。
```

验收：上层导演状态机不需要判断 SDK 类型。

### Task E：Edge/Cloud 分工

```text
实现现场 Edge Agent，将 STC 选择后的关键帧和事件上传云服务；本地保留检测跟踪和 PTZ 闭环。断网时写入本地 outbox，恢复后补传。任何云端超时不影响本地 Stop 和安全控制。
```

验收：断网 2 分钟仍能本地跟拍；恢复后事件按顺序上传且不重复。

## 10. 明天的停止条件

出现以下情况时立即使用降级方案，不继续硬攻：

- 官方 SDK 30 分钟内不能编译：先跑预编译 Demo，业务使用 OSC/UVC。
- X4 Air 实时预览不稳定：主线改为本地录制后下载分析。
- VideoLLM-online 环境 45 分钟内未启动：停用该基线，使用百炼 API。
- 云网络延迟过高：语义降为事件后分析，本地算法继续跟拍。
- Media SDK 导出失败：用官方 Studio 预先导出 MP4，保留自动镜头脚本和 FFmpeg 重构演示。

## 11. 安全与隐私

- 云台控制命令必须有范围、速率和超时限制。
- 任何相对 PTZ 移动在窗口失焦、连接丢失和程序退出时发送 Stop。
- 不暴露 SDK 服务到公网，只监听 localhost 或受控局域网。
- API Key、OSS 凭证、SDK 凭证放在环境变量或密钥服务中。
- 人脸和声音素材取得授权，Demo 后按约定删除原始数据。
- 不允许 LLM 调用固件升级、恢复出厂、格式化或删除素材。
