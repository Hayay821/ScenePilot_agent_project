# 今晚无硬件算法验证实施说明

目标：没有 X4 Air、Link 2 和官方云服务器时，完成一个可运行的“事件驱动 AI 跟拍导演”骨架，证明流式采样、STC 压缩、百炼视觉理解、事件时间线和导演决策可以闭环。

## 1. 今晚的完成定义

今晚结束前应得到以下可验证产物：

1. 输入一个本地 MP4 或摄像头视频。
2. 模拟实时播放，按时间顺序读取帧，而不是一次性分析完整视频。
3. STC 模块丢弃重复帧，保留变化明显的关键帧。
4. 批量将关键帧传给百炼视觉模型，返回结构化事件 JSON。
5. 状态机根据事件输出虚拟设备命令，如 `start_recording`、`track_subject`、`mark_highlight`。
6. 保存 `events.jsonl`、`commands.jsonl`、关键帧和运行指标。
7. 根据高光时间段，用 FFmpeg 导出至少一个短片。
8. 在不提供 API Key 时，可用 Mock 模型完成同一流程。

今晚不做：训练模型、部署 VideoLLM-online 8B、接入真实 SDK、生产级前端、复杂多机同步。

## 2. 公共数据选择

优先使用小而明确的视频，不要今晚下载大型数据集。

| 数据来源 | 用途 | 建议 |
|---|---|---|
| 自己用手机拍 30 到 60 秒动作视频 | 最快验证跟踪和事件 | 最优先，包含入场、动作、庆祝、离场 |
| Ego4D | 第一视角长视频与事件理解 | 只取少量公开样例；完整数据过大 |
| UCF101 / HMDB51 | 动作识别和动作强度 | 选择 3 到 5 个短片 |
| ActivityNet / Kinetics 样例 | 有时间标注的动作事件 | 只下载可合法获取的小样例 |
| 公开视频中的 equirectangular 360 样片 | 全景视角裁切 | 确认许可证，优先使用官方/Creative Commons 样片 |

为了避免数据下载阻塞，Claude Coding 应支持任意本地 MP4。测试素材由用户放入 `data/input/`。

## 4. 统一数据结构

Claude Coding 第一件事是定义并测试 Pydantic Schema。

```python
class FramePacket(BaseModel):
    source_id: str
    frame_index: int
    timestamp_ms: int
    image_path: str | None = None
    width: int
    height: int

class SelectedFrame(BaseModel):
    frame: FramePacket
    change_score: float
    novelty_score: float
    selection_reason: list[str]

class VideoEvent(BaseModel):
    event_id: str
    start_ms: int
    end_ms: int
    event_type: Literal[
        "subject_enter", "subject_leave", "action_start", "action_peak",
        "celebration", "occlusion", "scene_change", "unknown"
    ]
    subjects: list[str]
    description: str
    confidence: float
    highlight_score: float
    evidence_frame_ids: list[int]

class CameraAction(BaseModel):
    device: Literal["mock", "x4air", "link2"]
    action: Literal[
        "start_recording", "stop_recording", "track_subject",
        "set_composition", "mark_highlight", "recover_subject", "noop"
    ]
    args: dict
    reason: str
    confidence: float
```

## 5. STC 基线实现

### 5.1 输入采样

- 以视频原始时间戳模拟实时。
- 最初每秒读取 2 帧，和 VideoLLM-online 的训练采样思路保持一致。
- 所有帧缩放到最长边 384，保留宽高比。
- 维护 10 秒环形缓冲区，以便事件发生时回溯事件前画面。

### 5.2 选择规则

对相邻候选帧计算：

- 灰度绝对差均值 `frame_diff`。
- HSV 直方图距离 `hist_diff`。
- 感知哈希汉明距离 `phash_distance`。
- 可选主体框中心和面积变化 `subject_motion`。
- 可选音频 RMS 峰值 `audio_peak`。

建议第一版：

```text
change_score = 0.40 * frame_diff
             + 0.25 * hist_diff
             + 0.20 * subject_motion
             + 0.15 * audio_peak
```

入选条件：

- `change_score >= threshold`；或
- 距上一个入选帧超过 `max_gap_sec=3`；或
- 发生主体进入/离开、声音峰值、场景切换。

每个 4 秒窗口最多选择 4 帧，至少选择 1 帧。阈值放到配置文件，不散落在代码中。

### 5.3 必须输出的指标

```json
{
  "decoded_frames": 120,
  "selected_frames": 26,
  "compression_ratio": 0.7833,
  "api_batches": 7,
  "avg_semantic_latency_ms": 1820,
  "events": 5
}
```

## 6. 百炼 API 使用方式

使用 OpenAI Python SDK，Base URL：

```text
https://dashscope.aliyuncs.com/compatible-mode/v1
```

环境变量：

```text
DASHSCOPE_API_KEY=<不要写入代码或提交>
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_VL_MODEL=<从百炼控制台确认>
```

实现要求：

- 一次提交 2 到 4 张关键帧和它们的相对时间戳。
- 图片可先编码为 data URL；若接口/模型不接受，再上传 OSS 使用 URL。
- 要求模型只返回 JSON，并用 Pydantic 校验。
- 解析失败时重试一次，第二次失败记录错误并返回 `unknown`。
- API 调用必须有超时、指数退避、最大并发数和磁盘缓存。
- 缓存键由模型名、提示词版本和图片哈希构成。

提示词目标：

```text
你是实时摄影导演。以下图片按时间顺序来自连续视频。
用户目标：{user_intent}
请判断这段时间内是否发生值得改变拍摄策略的事件。
只返回符合给定 JSON Schema 的对象。不要输出 Markdown。
不要根据单帧猜测看不见的事实；无法判断时 event_type=unknown。
```

结构化输出至少包含：事件类型、开始/结束时间、主体、描述、置信度、高光分和证据帧。

## 7. 状态机

```text
IDLE
  -> subject_enter -> SEARCH
SEARCH
  -> stable_track -> TRACK
TRACK
  -> action_start -> RECORD
  -> lost_subject -> RECOVER
RECORD
  -> action_peak/celebration -> HIGHLIGHT
  -> inactivity_timeout -> TRACK
HIGHLIGHT
  -> save pre-roll + post-roll -> RECORD/TRACK
RECOVER
  -> subject_found -> TRACK
  -> timeout -> SEARCH
```

今晚所有设备操作由 Mock Adapter 写入 `commands.jsonl`。不能让语义模型绕过状态机直接执行动作。

## 8. 高光导出

每个高光事件导出：

```text
clip_start = max(0, event.start_ms - 3000)
clip_end   = min(duration, event.end_ms + 3000)
```

相邻或重叠片段应合并。第一版使用 FFmpeg concat 生成预览，不要求智能转场。

对于 360 equirectangular 样片，增加实验命令：使用 FFmpeg `v360` 输出固定 `yaw/pitch/fov` 的普通视角。今晚只需证明投影管线有效，自动轨迹留到下一阶段。

## 9. Claude Coding 任务单

按顺序执行，不要同时铺开全部功能：

### Task 1：项目骨架与 Schema

```text
在 project00 下创建 Python 3.11 项目。使用 Pydantic Settings 管理配置，定义 FramePacket、SelectedFrame、VideoEvent、CameraAction 和 RunMetrics。添加 pytest。不得写入任何密钥。
```

验收：Schema 测试通过；`.env.example` 存在。

### Task 2：流式视频输入

```text
实现 FileVideoSource，使用 OpenCV 或 PyAV 按时间戳迭代本地 MP4，支持 realtime=false 快速模式和 realtime=true 模拟实时模式。实现 10 秒 RingBuffer。
```

验收：对 30 秒视频输出单调递增时间戳；结束后正确释放文件。

### Task 3：STC 启发式压缩

```text
实现 STCAdapter 抽象接口和 HeuristicSTC。按 frame_diff、hist_diff、phash、max_gap 选择帧，输出选择原因和压缩率。阈值从配置读取。
```

验收：静态视频选择帧显著少于运动视频；至少有单元测试覆盖阈值和 max_gap。

### Task 4：语义 Provider

```text
实现 SemanticProvider 协议、MockSemanticProvider 和 DashScopeVLSemanticProvider。后者通过 OpenAI SDK 使用 DASHSCOPE_BASE_URL，发送多图和时间戳，要求 JSON 输出并经 Pydantic 校验，包含超时、重试、缓存和并发限制。
```

验收：无 Key 时 Mock 流程可运行；有 Key 时至少成功分析一批图片。

### Task 5：导演状态机

```text
实现纯函数式 DirectorStateMachine，将 VideoEvent 转换为 CameraAction。设备先使用 MockLink2Adapter 和 MockX4AirAdapter，只记录命令，不执行系统命令。
```

验收：覆盖正常跟拍、丢失恢复、事件高光和超时停止测试。

### Task 6：端到端 CLI

```text
实现命令 python -m app.cli analyze --input data/input/demo.mp4 --intent "跟拍穿红衣的人，记录成功动作和庆祝"。生成 keyframes、events.jsonl、commands.jsonl、metrics.json 和 highlights.mp4。
```

验收：一条命令完成；失败时返回非零退出码和可读错误。

## 10. 今晚实验矩阵

| 实验 | 变量 | 记录 |
|---|---|---|
| E1 无压缩 | 固定每秒 2 帧全部送模 | 请求数、延迟、事件结果 |
| E2 STC | 启发式压缩后送模 | 压缩率、请求数、事件结果 |
| E3 不同窗口 | 2 秒、4 秒、8 秒 | 延迟与上下文完整性 |
| E4 Mock/真实 API | 相同输入 | Schema 与状态机一致性 |
| E5 不同拍摄目标 | “跟拍人物”与“记录动作高潮” | 事件和命令是否随意图变化 |

今晚的核心结论应回答：STC 是否显著减少 API 输入；减少后是否仍发现人工标注的关键事件；模型输出能否稳定驱动受约束状态机。
