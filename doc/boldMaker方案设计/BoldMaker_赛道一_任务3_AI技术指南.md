## 1. 赛题解读：评审标准如何翻译成工程决策

官方评审：**技术创新 30% · 实现完整度 25% · 用户/应用价值 25% · 影像技术运用 20%**。

| 评审项 | 分值 | 任务3的责任 |
|---|---|---|
| 技术创新 | 30 | 不是发明新模型，而是**新的组合与交互范式**（如：语言驱动的成片 Agent、设备理解人的实时管线）。方案必须与 Insta360 产品强绑定，避免"放之四海皆准的 AI demo" |

任务与通用要求提示我们两个硬性事实：

## 3. 研究方向：三个候选 + 一个推荐

### 方案 A（推荐主线）：「AI 导播」——语言驱动的 360° 先拍后创 Agent

**一句话**：拍的时候不管构图（X5 全场景记录），拍完后用一句话让 Agent 看懂全部素材、自动写出"运镜脚本"并渲染成片，还可以继续用对话修改每一镜。

```
X5 全景素材(.insv/MP4)
   │  ffmpeg 抽帧 / 双鱼眼展开 / 球面切片多视角
   ▼
Qwen3-VL 视频理解 ──► 事件时间线 + 主体清单 + 精彩度打分(JSON)
   │
   ▼
LLM Agent（导演）：把用户一句话 + 时间线 → 「关键帧脚本」
   （每镜: t, yaw/pitch/fov/zoom，平滑约束）
   │
   ▼
球面重投影渲染(自研/ffmpeg v360 + 轨迹平滑) ──► 画面
   + 主体跟踪校正(YOLO-World + SAM2 + ByteTrack 保证主体不丢)
   + Whisper/FunASR 字幕 + 节拍卡点(librosa)
   ▼
Gradio Web UI：「再来一版：多给左边球门一点镜头」→ 增量重渲染
```

- 为什么契合命题：全景重投影本来就是"设备理解人"的最佳载体；而影石官方 App 的 AI 关键帧**不能对话、不能理解语义事件**（"进球瞬间"、"她笑的时候"），这就是我们的创新缝隙。
- 创新点表述：**从"时间轴剪辑"到"意图剪辑"（intent-based editing）**；先拍后想 × 大模型 = 相机成为导演。
- 影像技术运用分：球面几何、双鱼眼展开、陀螺仪数据、防抖（Gyroflow/自研平滑）全用上。
- 风险：渲染一致性、SDK 接入深度（可用"离线文件输入"绕开 SDK，把 SDK 当加分项）。

### 方案 B（实时线，可作为 A 的直播扩展或独立备胎）：端侧 AI 虚拟摄影师

Link/Ace Pro 2 作 UVC 取流 → YOLO-World（开放词汇："穿红衣服的人"、"蛋糕"、"进球"）+ SAM2 视频分割 + OC-SORT 跟踪 + 构图规则（三分法/美学裁剪模型）→ 实时裁切推流 / 反向通过 SDK 控制云台与录制启停。

- 优点：现场演示冲击力极强（观众喊一句话，镜头立刻对准他）。
- 缺点：与 Link 内置 AI 取景同质化风险；实时性能在大场景下不稳定。
- 定位：**如果做 A，B 作为"直播模式"章节；如果 A 受阻，B 是独立主线。**

### 方案 C（最快出片，兜底方案）：运动场景自动成片流水线

6 大训练场实拍（骑行/滑板/跑步等）→ Ace Pro 2/GO Ultra 素材 → 动作识别（VideoMAE zero-shot 或姿态启发式：腾空高度、翻转周数）+ 多模态精彩度打分 → 自动高光集锦 + 卡点配乐 + 字幕 + 竖屏重构图（9:16 适配社媒）。

- 优点：48h 内**最稳**、素材现场即可生产、"影像技术运用"天然达标。
- 缺点：市面上"AI 自动剪辑"产品多，创新分要靠"动作理解深度 + 现场实景叙事"拉回来。

### 决策矩阵与最终建议

| 维度 | A 语言驱动 360° Agent | B 实时虚拟摄影师 | C 运动自动成片 |
|---|---|---|---|
| 技术创新 30% | ★★★★★ | ★★★★ | ★★★ |
| 实现完整度 25%（48h 可行性） | ★★★☆ | ★★★ | ★★★★★ |
| 用户价值 25% | ★★★★（Vlog/家庭/赛事人群广） | ★★★★（直播/会议） | ★★★★（运动人群精准） |
| 影像技术 20% | ★★★★★ | ★★★★ | ★★★★ |
| Demo 冲击力 | ★★★★（对话改片很抓人） | ★★★★★ | ★★★★ |

**推荐：以 C 的"自动成片流水线"为主干工程（保证完成度），以 A 的"对话式导演 Agent"为灵魂交互（保证创新分），B 作为直播彩蛋（时间富余才做）。**
对外统一产品故事：「**拍前不设防，拍后可对话**」——一个端到端的 AI 影像再创作系统：硬件层吃影石全系素材，理解层用千问多模态，输出层自动成片 + 对话式修改。

## 4. 技术栈与模型清单（任务3 核心弹药库）

### 4.1 选型总表（全部为可离线部署的开源权重或官方 API）

| 环节 | 首选 | 备选/兜底 | 说明 |
|---|---|---|---|
| 开放词汇检测 | **YOLO11 + YOLO-World** (ultralytics) | Grounding DINO 1.5 / **SAM 3**（文本概念提示分割） | "用自然语言指定拍摄主体"的关键；YOLO11-seg 兜底 |
| 视频目标分割 | **SAM 2**（流式，GPU 实时） | XMem | 给定第一帧点击/检测框 → 全程主体 mask，用于构图保证主体不出画 |
| 多目标跟踪 | **OC-SORT / BoT-SORT**（ultralytics 内置） | ByteTrack | 低代码：`model.track()` 一行起步 |
| 人体姿态 | **MediaPipe Pose**（实时） | RTMPose (MMPose) / YOLO11-pose | 动作分析、腾空/翻转启发式规则的输入 |
| 动作识别 | **VideoMAE v2 zero-shot** 或 CLIP 帧级分类 | ActionCLIP；纯规则（姿态角速度/垂直速度峰值） | 比赛场景用"规则+打分"足够，别微调，没时间 |
| 精彩度打分 | **Qwen3-VL**（视频片段级问答打分，结构化 JSON 输出） | 本地 InternVL/Qwen2.5-VL-7B 兜底 | 官方生态位，评审好感度高 |
| 语言理解/脚本生成 | **Qwen3-VL / Qwen-Max（百炼 API）** | 本地 Qwen3-14B（vLLM/Ollama） | Agent 的"导演大脑" |
| 字幕/ASR | **FunASR（阿里系，中文强）** | faster-whisper large-v3 | 与千问同生态，加分 |
| TTS 解说 | CosyVoice 2（阿里开源） | edge-tts | "AI 体育解说"彩蛋功能 |
| 音乐卡点 | librosa（beat tracking） + ffmpeg | madmom | 自动剪辑的节奏骨架 |
| 画质增强 | **Real-ESRGAN**（图像）/ **VEnhancer**（视频，扩散式） | GFPGAN/CodeFormer（人脸老照片修复） | "老素材焕新"方向的现成模块，接入即可演示 |
| 防抖 | **Gyroflow**（CLI，读影石内嵌陀螺仪） | 光流稳像（opencv vidstab 等价实现） | 体现"真正用了影石数据" |

| 轨迹平滑 | 临界阻尼平滑 / Catmull-Rom + 速度约束 | 简单高斯滤波 | "虚拟云台"手感决定成片观感，花 10% 时间打磨 |
| Agent 编排 | 手写状态机（推荐，可控） | LangGraph | 48h 内别迷信框架 |
| Demo 前端 | **Gradio** | Streamlit | 半天能搭出"上传→设置→出片→对话修改"界面 |
| 部署 | conda 环境 + Dockerfile | — | 9/20 前打成镜像/安装脚本，防现场网络 |

## 5. 最小可跑链路（Walking Skeleton）与模块设计

### 5.1 设计原则

- **先通后优**：9/20 前用任意一段下载的 360° 测试片把全链路跑通（哪怕每步都是占位实现）。
- **每个模块可降级**：API 挂了有本地小模型兜底；重投影渲染挂了有 ffmpeg v360 固定轨迹兜底；主体跟踪挂了有"中央裁切"兜底。**降级 ≠ 失败，Demo 不停摆是第一原则。**
- **数据契约先行**：模块间只通过两个 JSON（见 5.3）通信，方便与队友并行开发。

### 5.2 核心链路分步

```
[1] 摄入 ingest.py      : .insv/.mp4 → 探测(ffmpeg/ffprobe/Gyroflow) → 统一转 3840x1920 equirect MP4 + 抽 1fps 帧
[2] 感知 perceive.py     : 1fps 帧 → YOLO-World 检测 + ByteTrack → 主体轨迹表
[3] 理解 understand.py   : 多视角切片(前/左/后/右 4 个 perspective 视图拼网格) → Qwen3-VL
                           → 输出 Timeline JSON: 事件、主体、精彩分、建议镜头
[4] 导演 direct.py       : (用户 query + Timeline) → LLM → ShotList JSON(关键帧脚本)
                           约束校验: fov∈[40,100], 角速度上限, 主体不出画(用轨迹表校验)
[5] 渲染 render.py       : ShotList + equirect → 球面重投影逐帧 → ffmpeg 编码
                           平滑: 临界阻尼; 校正: SAM2 mask 质心偏移补偿
[6] 音频 audio.py        : FunASR 字幕(烧录) + librosa 节拍对齐裁剪 + BGM(Flova [现场确认]/本地曲库)
[7] 对话 chat.py         : "把第2镜换成竖屏" / "多给观众反应" → 只重渲对应 shot
[8] UI ui.py (Gradio)    : 上传 → 分析进度 → 预览 → 对话修改 → 下载成片
```

### 5.3 模块间数据契约（与队友对齐的接口文件）

`Timeline.json`（步骤 2/3 产出）
```json
{
  "duration": 312.5, "camera": "X5", "src": "clip_001",
  "subjects": [{"id": 0, "label": "红衣滑雪者", "first_t": 3.2, "last_t": 89.0, "track_quality": 0.86}],
  "events": [
    {"t0": 41.0, "t1": 47.5, "type": "jump_landing", "highlight_score": 9.1,
     "caption": "腾跃落地激起雪雾，主体居中", "suggested_shot": {"yaw": 12.3, "fov": 78}}
  ]
}
```
`ShotList.json`（步骤 4 产出，渲染器唯一输入）
```json
{"shots": [{"id": 1, "t0": 41.0, "t1": 46.0, "keyframes": [
    {"t": 41.0, "yaw": 10, "pitch": -5, "fov": 90},
    {"t": 46.0, "yaw": 25, "pitch": 0,  "fov": 60}],
  "target_subject": 0, "aspect": "16:9"}]}
```

```python
# 球面重投影核心数学(附录 B, 10 行)
def sphere_reproject(equirect, yaw, pitch, fov, out_hw):
    h, w = out_hw
    fx = (w/2)/np.tan(np.radians(fov)/2)
    dirs = pixel_dirs(h, w, fx)                    # 针孔反投影
    dirs = rot_x(pitch) @ rot_y(yaw) @ dirs.T      # 虚拟云台旋转
    lon, lat = np.arctan2(dirs[0], dirs[2]), np.arcsin(np.clip(dirs[1],-1,1))
    mapx = (lon/(2*np.pi)+0.5)*EQR_W; mapy = (0.5-lat/np.pi)*EQR_H
    return cv2.remap(equirect, mapx, mapy, cv2.INTER_LINEAR)
```
