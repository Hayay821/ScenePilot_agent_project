# Bold Maker 智能影像挑战赛
## 赛道一：AI + 影像产品开发项目指导文档

版本：2026-09-16

本文服务于当前负责 AI 技术、模型和技术方案的成员。文档将比赛公开信息、影石产品能力、可在 4 天内完成的工程范围和可用于答辩的产品叙事合并到一个执行方案中。

---

## 1. 先给结论

### 推荐项目：`AI 导演台 / Insta360 StoryPilot`

一句话：**用户只需要说出“我想记录什么”，系统就能理解多机影像，自动找出关键时刻、判断镜头质量、选择最佳视角，并生成可解释、可修改的短片。**

示例指令：

> “把我今天在 Club Med 的攀岩挑战做成 45 秒热血短片，突出第一次成功登顶，保留失败和队友鼓励，竖屏，适合发给朋友。”

系统输出：

1. 精彩片段时间线：准备、尝试、失败、鼓励、成功、庆祝。
2. 每个片段的来源设备、时间点、人物和动作标签。
3. 自动选取的主镜头与补充镜头。
4. 一段 9:16 短视频和一个可编辑的剪辑计划。
5. 自动生成的标题、字幕、旁白建议和“为什么选中这一段”的解释。

### 为什么选这个方向

- 直接命中官方赛题的 AI 智能拍摄、AI 影像处理和多设备联动。
- 同时体现影石的差异化：360 度素材不是只能导出普通视频，而是允许 AI 在拍摄后重新决定“看哪里”。
- 不把成败押在尚未确认的实时硬件控制 API 上。即使现场 SDK 受限，也能以本地素材导入完成主链路。
- Demo 容易看懂：同一批原始素材与普通手工剪辑结果对比，突出“少操作、不错过、可解释、可修改”。
- 适合 4 天开发：先完成离线素材分析和成片，再增加实时控制、设备联动和 360 重构。

### 不建议作为主项目的方向

- 只做“调用大模型写标题”：影像技术含量和用户价值不足。
- 只做普通 AI 自动剪辑：容易与现有剪辑软件同质化，没有使用影石设备的理由。
- 一开始就做端侧实时目标检测和相机云台控制：硬件接口、性能、权限和测试风险过高。
- 同时支持所有四种设备的完整控制：会分散开发资源。应该先用统一素材协议做设备无关主链路，再展示不同设备的适配价值。

## 2. 比赛目标与硬性要求

根据组内提供的官方赛事说明，赛道一的核心命题是“让相机自己变聪明”，基于影石产品和开放 SDK，结合大模型，开发 AI 驱动的智能拍摄、影像处理或交互方案。

官方给出的方向包括：

- AI 智能拍摄：自动取景构图、主体跟拍、精彩时刻捕捉、运动动作识别。
- AI 影像处理：自动剪辑、智能配乐字幕、全景内容智能重构、老素材画质增强。
- 智能交互：语音、手势、无接触拍摄控制、多设备联动、可穿戴交互。
- 软硬结合：影石相机、SDK、配件或原型产品。

## 3. 产品定义与用户流程

### 目标用户

首选用户：**有多台运动相机素材，但没有时间或能力剪片的活动参与者、户外爱好者和短视频创作者。**

他们通常面对这些问题：

- 拍了很多素材，真正精彩的瞬间藏在数小时视频里。
- 360 视频视角自由，但手动重新取景耗时。
- 不知道该用哪个设备、哪个角度或哪段素材做主镜头。
- 自动剪辑往往只有“套模板”，不能理解这次拍摄想表达的故事。
- AI 结果缺少可解释性，用户不敢直接发布，也不容易修改。

### 核心交互

1. 选择一个任务模板：运动挑战、旅行记录、活动回顾、人物故事。
2. 导入 X5、Ace Pro 2、GO Ultra、Link 中任意设备拍摄的素材。
3. 输入一句话目标，或选择时长、画幅、情绪和发布平台。
4. 系统先展示“素材地图”：人物、动作、声音、清晰度、时间轴和设备来源。
5. 系统生成故事线，并允许用户点选“更突出成功”“减少重复”“保留队友声音”等偏好。
6. 导出短片，同时保留可编辑剪辑计划 JSON，方便继续修改。

### MVP 的最小闭环

```text
视频/图片导入
    -> 统一媒体信息与缩略图
    -> 视频切片和关键帧抽取
    -> 目标/人物/动作/语音/画质分析
    -> 用户意图解析
    -> 片段评分和故事排序
    -> 360 视角建议或普通视频裁切
    -> 字幕/标题/配乐点建议
    -> 预览与导出
```

“自动控制相机”属于第二阶段增强功能，不应成为 MVP 的单点故障。

## 4. 影石设备能力与现场核验矩阵

下表用于做技术边界判断。公开产品介绍能确认产品定位和基本影像形态，但赛事现场提供的 SDK、固件版本、权限和可用接口必须以官方技术包为准。没有拿到接口文档前，不要在提案中承诺具体 API 名称。

| 设备 | 适合在项目中的角色 | 主要输入/输出 | 可能的外部连接 | AI 项目价值 | 现场必须确认 |
|---|---|---|---|---|---|
| X5 全景相机 | 全景主素材、事后自由取景、环境上下文 | 360 视频/照片，通常为高码率全景素材；导出后可转普通视角 | 手机 App、无线传输、USB/存储卡；具体 SDK 能力以技术包为准 | 让 AI 决定时间点和观看方向，展示“拍完再构图” | 是否可远程开始/停止、预览流格式、全景姿态元数据、下载方式 |
| Ace Pro 2 | 第一视角、运动主镜头、低光或高动态补充 | 普通广角视频/照片、音频；可能包含陀螺仪等元数据 | 手机 App、USB、存储卡；具体控制接口以技术包为准 | 用作清晰、稳定、可直接发布的主镜头 | 实时预览、控制命令、文件拉取、元数据导出、编码格式 |
| GO Ultra | 轻量、第一视角、身体/物体附近视角 | 小型运动视频/照片；佩戴位置带来独特视角 | 充电盒/手机 App/USB/存储；具体 SDK 以现场资料为准 | 提供“人正在经历什么”的沉浸视角 | 是否开放实时流、设备枚举、控制和素材同步方式 |
| Link | 人像、桌面演示、直播或语音交互中的正面画面 | 普通摄像头视频和音频，适合实时输入 | USB，可能支持标准摄像头协议；高级控制以官方文档为准 | 让系统看到用户当前状态，支持语音/手势交互 Demo | UVC/音频设备模式、云台/构图控制、分辨率和帧率 |

### 接口设计原则

将输入层抽象成统一的 `MediaAsset`，不要让上层业务直接依赖某个设备 API：

```json
{
  "asset_id": "x5_001",
  "device": "X5",
  "path": "./assets/x5_001.insv",
  "media_type": "video",
  "projection": "equirectangular",
  "duration_ms": 183000,
  "fps": 30,
  "audio": true,
  "capture_time": "2026-09-22T14:10:08+08:00",
  "gps": null,
  "orientation": null
}
```

所有设备适配器只负责转换为这个结构。这样即使某一台设备无法实时连接，也能直接导入其导出文件完成 Demo。

### 现场前 60 分钟核验清单

- 获取并保存官方 SDK、示例代码、许可证和依赖版本。
- 确认四台设备的固件、存储卡、连接模式和供电状态。
- 对每台设备完成一次“连接、拍摄、传输、读取、解析、断开”测试。
- 保存一段 10 秒样片和对应的元数据，记录原始文件格式。
- 询问哪些接口允许在参赛作品中展示，哪些只能用于现场体验。
- 记录失败时的替代路径：本地文件、USB 导入、标准 UVC、预录素材。

## 5. 推荐技术架构

### 总体分层

```text
前端：Next.js/React 或 Streamlit 原型
  - 素材上传、任务描述、分析进度、时间线、预览、导出

后端：Python FastAPI
  - 任务队列、媒体分析编排、模型调用、结果 JSON

媒体层：FFmpeg + OpenCV + PyAV
  - 转码、抽帧、音频拆分、缩略图、时长和帧率读取

视觉层：YOLO / RT-DETR + ByteTrack + MediaPipe
  - 人/物检测、跨帧跟踪、姿态和运动强度

语音层：FunASR 或 Whisper
  - ASR、时间戳、关键词和情绪线索

多模态层：赛事提供的阿里千问多模态能力
  - 用户意图解析、关键帧描述、片段摘要、故事线和字幕文案

影像层：FFmpeg + OpenCV + 360 视角裁切工具
  - 普通视频裁切、拼接、字幕和代理文件；360 先做可控的视角预览

存储层：本地目录 + SQLite/JSON
  - 4 天活动现场优先保证可重启、可追踪和可演示
```

### 推荐模型组合

| 任务 | 首选 | 备选/降级 | 输出 |
|---|---|---|---|
| 用户意图解析 | Qwen 多模态/文本模型 | 规则 + JSON Schema | 主题、主体、情绪、时长、画幅、偏好 |
| 关键帧语义理解 | Qwen-VL 多模态能力 | 本地 CLIP/SigLIP + 少量人工标签 | 场景、人物、动作、精彩度解释 |
| 人物/物体检测 | YOLO 系列 | OpenCV 基础特征 | 框、类别、置信度 |
| 人物跟踪 | ByteTrack | 按时间相邻匹配 | track_id、出现区间 |
| 动作/姿态 | MediaPipe Pose | 光流、帧差、速度启发式 | 姿态关键点、运动强度 |
| 语音识别 | FunASR | Whisper | 文本、时间戳、关键词 |
| 镜头质量 | Laplacian 清晰度、曝光、抖动指标 | 纯多模态判断 | 清晰度、过曝、黑帧、稳定性 |
| 配乐 | 赛事允许的创作工具/音乐素材 | 只输出音乐入点建议 | 节奏点、情绪、音量自动化 |
| 360 取景 | 先用等距投影到普通视角的裁切 | 直接调用官方 SDK/工具 | yaw、pitch、FOV、输出视频 |

### 模型使用边界

- Qwen 负责高层语义和自然语言，不负责逐帧实时检测。
- 本地视觉模型负责廉价、可重复的结构化信号。
- 不要把 4K 全视频逐帧发送给大模型。先用 FFmpeg 抽帧、镜头切分和低分辨率代理视频做候选筛选，再对 Top-K 片段调用多模态模型。
- 所有模型输出必须经过 Pydantic/JSON Schema 校验；模型输出不能直接拼接 FFmpeg 命令。
- API Key、素材和参赛者人脸数据不能写入 Git，也不要在前端暴露密钥。
- 如果赛事要求使用指定的阿里千问能力，必须把 Qwen 放在关键智能链路中，不能只在宣传页提及。

## 6. 核心算法：从素材到故事

### 6.1 预处理

1. 为每个文件计算 `sha256`，避免重复分析。
2. 读取时长、帧率、分辨率、音频轨和创建时间。
3. 生成 360p 或 540p 代理视频，原始文件只用于最终导出。
4. 每 1 秒抽取一帧；用镜头切分或颜色/结构变化减少冗余。
5. 音频单独转为 16 kHz 单声道，供 ASR 使用。
6. 写入任务状态：`queued -> preprocessing -> analyzing -> planning -> rendering -> done`。

### 6.2 片段特征

对每个候选片段计算：

```text
semantic_score    语义相关度：是否包含用户指定主体/动作/地点
event_score       事件强度：动作速度、姿态变化、欢呼、声音峰值
quality_score     画质：清晰度、曝光、遮挡、黑帧、抖动
coverage_score    叙事覆盖：是否填补准备/过程/结果等故事节点
novelty_score     去重分：与已选片段的视觉和语义差异
device_score      设备价值分：是否体现 360 或独特第一视角
```

建议的初始评分：

```text
total = 0.30 * semantic_score
      + 0.25 * event_score
      + 0.15 * quality_score
      + 0.15 * coverage_score
      + 0.10 * novelty_score
      + 0.05 * device_score
```

这个公式不是最终研究成果，而是可解释的工程基线。Demo 中要展示每个片段被选中的原因，例如“动作速度高、包含目标人物、存在队友欢呼、来源为 X5 全景素材”。

### 6.3 用户意图 JSON

让多模态模型严格返回类似结构：

```json
{
  "subject": ["我", "队友"],
  "activity": ["攀岩", "成功登顶"],
  "story_arc": ["准备", "挑战", "失败", "鼓励", "成功", "庆祝"],
  "tone": "热血但真实",
  "duration_sec": 45,
  "aspect_ratio": "9:16",
  "must_keep": ["第一次成功", "队友鼓励"],
  "avoid": ["重复动作", "长时间静止"],
  "preferred_devices": ["X5", "Ace Pro 2", "GO Ultra"]
}
```

### 6.4 360 影像的创新点

不要把 360 只当普通素材。对 X5 片段，系统可以：

- 从全景帧里检测人物和动作，得到目标在球面上的方向。
- 根据动作方向、人物朝向和故事节点计算视角轨迹。
- 在关键帧上生成 `yaw/pitch/fov`，中间用平滑插值。
- 输出一个正常 16:9 或 9:16 视频，让用户看到“拍摄时不用精确瞄准，AI 在后期替你选择镜头”。
- 在时间线里展示小地图或视角轨迹，证明不是随机裁切。

4 天内不必从零实现完整球面渲染。优先使用官方导出能力或经过验证的 equirectangular 到 perspective 转换库；若库不稳定，先输出可演示的视角参数和预渲染结果。

## 7. 开发范围：P0、P1、P2

### P0：必须完成

- 上传 2 到 4 段真实素材。
- 支持普通视频和至少一种全景素材的识别或导入。
- 输入一句自然语言拍摄目标。
- 抽帧、ASR、人物/动作/画质分析。
- 输出 Top-K 精彩片段和解释。
- 生成一条 30 到 60 秒视频，或生成可被剪辑工具读取的剪辑计划。
- 展示设备来源、时间码和选段理由。
- 失败时能用预录素材完整演示。

### P1：建议完成

- X5 片段自动视角建议和普通视角导出。
- “更热血/更真实/突出某人/减少重复”等二次指令。
- 导出 SRT 字幕、标题和封面文案。
- Link 作为实时人像或语音输入设备。
- 接入赛事提供的创作工具链进行配乐或最终渲染。

### P2：有余力再做

- 通过 SDK 远程开始/停止拍摄。
- 多设备按统一时间基准同步。
- 拍摄前根据用户目标给出构图/设备建议。
- 拍摄过程中检测“关键事件即将发生”，自动打标或触发录制。
- 端侧模型、低延迟实时预览和无网运行。

P2 不得影响 P0 的稳定性。

## 8. 4 天现场排期

### 第 1 天：核验、取样、跑通媒体管线

- 上午：确认 SDK、设备固件、网络、算力和存储权限。
- 中午前：四台设备各拍一组 10 到 30 秒样片，记录文件和元数据。
- 下午：完成素材导入、代理视频、抽帧、ASR 和基础检测。
- 晚上：选定一组可控场景，固定 Demo 素材和人工标注基准。

交付物：设备能力表、样片目录、可重复运行的预处理脚本。

### 第 2 天：完成智能分析和提案

- 上午：实现意图 JSON、片段特征和评分。
- 下午：将分析结果展示为素材时间线，至少生成一版故事线。
- 9 月 22 日 10:00 前：提交提案，提案中只写已经验证或明确标注为计划的能力。
- 晚上：访谈目标用户，收集真实选择和修改反馈。

交付物：能从素材生成 Top-K 片段的后端、用户访谈记录、提案。

### 第 3 天：成片、问卷和设备特色

- 上午：实现 360 视角建议或等距投影到普通视角。
- 下午：接入字幕、标题、配乐点和视频导出。
- 9 月 23 日 12:00 前：提交用户访谈问卷和行业调研问卷。
- 晚上：加入一次真实设备控制或标准连接能力；如果失败，保留稳定的文件导入方案。

交付物：第一版完整 Demo、问卷材料、可解释时间线。

## 9. 你负责的任务 3：学习与执行清单

### 必须掌握

- Python、FastAPI、Pydantic、异步任务和日志。
- FFmpeg：探测、转码、抽帧、音视频合成、字幕、裁切。
- OpenCV 或 PyAV：视频读取、关键帧、清晰度和运动指标。
- Qwen 多模态 API：图片/视频帧输入、结构化输出、重试和限流。
- YOLO/RT-DETR 推理和 ByteTrack 基础。
- FunASR 或 Whisper：时间戳、中文识别和字幕导出。
- JSON Schema：约束模型输出，保证下游稳定。
- 基础 Git、环境变量、依赖锁定和可复现实验。

### 建议学习顺序

1. 先用 FFmpeg 对一段视频完成抽帧、转码和字幕烧录。
2. 再完成“关键帧 + Qwen 描述 + JSON 保存”。
3. 加入 ASR 时间戳和人物/动作检测。
4. 用固定权重生成片段排序，不要一开始训练新模型。
5. 最后再做全景视角和硬件 SDK 适配。

### 不建议在比赛中学习的内容

- 从零训练视频理解模型。
- 自己实现完整视频编码器或 360 球面渲染器。
- 为了“有模型”而训练没有数据和评估集的分类器。
- 同时接入多个付费 API，导致现场密钥、网络和计费风险。

## 10. 研究方向与可写入提案的创新点

### 研究问题

> 当用户只提供自然语言目标，而不是逐段剪辑指令时，如何利用多设备、多视角和多模态信号，自动生成一条符合用户意图、且可以解释和修改的影像故事？

### 创新点 1：意图驱动，而不是模板驱动

传统自动剪辑通常先选模板，再把素材塞进去。StoryPilot 先把用户语言解析为“主体、事件、情绪、叙事节点和禁用内容”，再选择素材。因此同一批素材可以生成“热血版”“真实纪录版”“队友情谊版”。

### 创新点 2：360 后构图

X5 记录的是完整空间，系统不要求拍摄者当下准确瞄准。AI 在后期根据人物、动作和故事节点生成视角轨迹，把 360 的“全记录”转化为“可叙事的镜头”。

### 创新点 3：多设备角色分工

不是简单拼接四个视频，而是给设备分配角色：X5 负责环境和全局，Ace Pro 2 负责稳定主镜头，GO Ultra 负责沉浸第一视角，Link 负责正面人物和语音交互。系统按片段特征选择设备，而不是默认优先某个文件。

### 创新点 4：可解释剪辑

每个片段都有来源、时间码、检测证据和选择理由。用户能删除、替换和重新描述，不会面对一个无法修正的黑盒成片。这一点也方便评委判断系统确实使用了 AI 和影像分析。

### 创新点 5：从拍摄后走向拍摄前

在 P2 阶段，用户先说目标，系统给出“用哪台设备、放在哪里、需要拍多久”的建议；拍摄后再自动完成剪辑，形成“目标理解 -> 拍摄建议 -> 智能记录 -> 自动成片”的闭环。

## 11. 用户访谈与行业调研

### 用户访谈对象

至少选择 3 类人中的 3 人：

- 经常拍运动/旅行视频但很少剪辑的人。
- 使用过运动相机或 360 相机的创作者。
- 活动组织者、教练、带队者或需要复盘影像的人。

### 每人至少 10 个问题

1. 你最近一次拍摄是什么场景，使用了什么设备？
2. 一次拍摄大约产生多少素材和时长？
3. 你最想保留的瞬间是什么？当时为什么重要？
4. 你现在如何找到精彩片段？花多长时间？
5. 你是否使用过自动剪辑或 AI 剪辑？哪里有用？
6. 哪些自动结果会让你不信任或必须手改？
7. 你会不会用 360 相机？最难理解或操作的部分是什么？
8. 如果系统让你用一句话描述想要的视频，你会怎么说？
9. 你更在意成片速度、画质、故事完整度还是可控性？请排序。
10. 你是否愿意让系统分析人脸、声音和动作？有什么隐私边界？
11. 你会使用哪些发布比例、时长和平台？
12. 如果系统给出每个选段的理由，你是否会更愿意采用？

记录要求：不要只记“用户觉得很好”。记录原话、当前替代方案、频率、耗时、付费意愿、无法接受的错误和用户实际选择。

### 行业调研应回答

- 运动相机和 360 相机为什么能记录更多画面，但用户仍然难以产出内容？
- 现有剪辑工具已经提供哪些自动剪辑、追踪、字幕和重构能力？
- 现有工具的切入口是模板、效果还是用户意图？
- 影石设备的 360、多设备和第一视角组合带来什么独特数据？
- 作品相比手机相册、剪辑软件和影石现有 App 的新增价值是什么？
- 目标用户愿意用什么方式输入意图，最终结果需要什么可控性？

行业调研的结论不要写成“市场很大”。应落到：**已有方案解决了什么、没解决什么、我们用哪项影石能力切入、为什么 4 天 Demo 足以证明假设。**

## 12. Demo 和答辩脚本

### 90 秒产品演示

1. 展示一堆来自 X5、Ace Pro 2 和 GO Ultra 的原始素材，说明用户不知道看哪里。
2. 输入：“生成 45 秒竖屏攀岩挑战，突出第一次成功，保留队友鼓励。”
3. 展示系统识别到的人物、动作、欢呼和设备来源。
4. 展示时间线：准备、失败、鼓励、成功、庆祝。
5. 点击 X5 片段，展示 AI 选择的视角轨迹。
6. 播放成片，并演示一句修改：“少一点失败，多保留成功后的反应。”
7. 展示导出视频、字幕和可编辑剪辑计划。

### 评委可能问的问题

**问：和现有自动剪辑有什么不同？**

答：我们的输入不是模板选择，而是用户对故事的自然语言意图；系统同时利用跨设备时间线、动作/声音事件和 X5 全景视角，并且对每个选段给出来源和理由。

**问：如果没有 SDK 或网络怎么办？**

答：核心链路支持本地素材导入和代理视频分析，设备实时控制是增强层。这样作品仍然完整，同时可以在有 SDK 时展示软硬件联动。

**问：Qwen 在系统里做了什么？**

答：Qwen 负责将用户目标转成结构化剪辑意图，并理解候选关键帧/片段的语义，生成故事节点和字幕建议；检测、跟踪、画质等低层信号由本地视觉和音频模块提供。

**问：是不是只是在调用 API？**

答：模型只是语义层。作品自己实现了媒体预处理、跨设备统一协议、片段特征、可解释排序、全景视角决策和可编辑导出，API 失败时仍有规则和本地模型降级。

**问：隐私怎么处理？**

答：Demo 默认使用现场授权素材；系统保留本地代理和结构化分析结果，上传多模态 API 前降低分辨率并明确告知；参赛后可增加本地推理、脱敏和素材自动删除策略。

## 13. 风险与降级策略

| 风险 | 影响 | 预案 |
|---|---|---|
| SDK 未开放或文档不完整 | 无法实时控制 | 使用真实设备导出的素材，展示统一适配层 |
| 网络或 API 限流 | 分析无法完成 | 缓存关键帧；准备预计算 JSON；本地规则排序兜底 |
| 原始素材太大 | 处理慢、磁盘满 | 代理视频 + Top-K 精选 + 最终才读原始文件 |
| 360 转码失败 | 特色能力无法播放 | 输出视角参数、预渲染短片和普通视频版本 |
| 中文 ASR 错误 | 字幕质量差 | 展示人工修订入口，保留无字幕版本 |
| 人物跟踪串 ID | 故事选错人 | 允许手工指定主体或在 Demo 素材中控制人数 |
| 模型输出格式错误 | 后端崩溃 | Schema 校验、重试、默认值和人工确认页 |
| 设备电量/存储不足 | 无法采样 | 第一晚完成全部录制，准备固定素材包 |
| 评委现场网络不同 | Demo 失败 | 启动前自检，准备离线预览和屏幕录制 |

### 必备离线包

- 3 组已经拍好的素材，每组不超过 2 分钟。
- 低分辨率代理视频和关键帧分析结果。
- 已生成的成片、SRT、缩略图和剪辑 JSON。
- 本地模型权重或可用的规则降级脚本。
- 一键启动脚本、依赖锁定文件和环境变量模板。
